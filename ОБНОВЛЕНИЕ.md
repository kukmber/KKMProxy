# Как обновлять и выпускать KKMProxy

Всё делается в терминале **Ubuntu (WSL)**, из папки проекта:

```bash
cd ~/ByeByeDPI
```

## Коротко

```bash
./scripts/whats-new.sh                           # что нового у авторов
./scripts/update-cores.sh                        # 1. обновить ядра
./gradlew :app:testDebugUnitTest assembleDebug   # 2. проверить сборку
./scripts/install-phone.sh                       # 3. проверить на телефоне
./scripts/release.sh 1.0.2 "обновил ядра"        # 4. выпустить релиз
```

Дальше — то же самое подробно.

## Что происходит само

**Ядра обновляются без вас.** Каждый понедельник GitHub сам обновляет ByeDPI, hev-socks5-tunnel и mihomo до свежих релизов, собирает и прогоняет тесты. Если всё в порядке — открывает pull request «Обновление ядер [release]»: https://github.com/kukmber/KKMProxy/pulls

От вас нужно одно: проверить сборку на телефоне (по желанию) и нажать **Merge**. После слияния версия поднимется, тег поставится, релиз соберётся и опубликуется — тоже само. Друзьям приложение предложит обновиться в течение суток.

Если сборка с новыми ядрами падает, pull request не создаётся: значит, обновление сломало проект и надо разбираться руками.

**Что не делается само:** TgWsProxy и ByeByeDPI — про них раз в неделю заводится задача со списком изменений: https://github.com/kukmber/KKMProxy/issues

Версии всех компонентов видно и в приложении: «Настройки» → «Обновления».

## Когда делать руками

Ручной путь ниже нужен, когда не хочется ждать понедельника или когда что-то пошло не так.

## Шаг 1. Обновить ядра

```bash
./scripts/update-cores.sh
```

Что делает сам:

| Компонент | Действие |
|---|---|
| ByeDPI | переводит подмодуль на свежий релиз |
| hev-socks5-tunnel | то же, вместе с вложенными подмодулями |
| mihomo | меняет версию в `app/build.gradle.kts` (ядро скачается при сборке) |
| TgWsProxy | **только сообщает** о новой версии |
| ByeByeDPI | **только сообщает** о новой версии |

Назад не откатывает: если подмодуль стоит на коммите новее последнего релиза, оставит как есть.

## Шаг 2. Проверить сборку

```bash
./gradlew :app:testDebugUnitTest assembleDebug
```

Нужно увидеть `BUILD SUCCESSFUL`. Шаг обязателен: обновление ядра уже ломало сборку (не хватало вложенного подмодуля lwip у hev).

При ошибке ищите в выводе строки на `e:` (Kotlin) или `error:` (нативный код). Готовые файлы — в `app/build/outputs/apk/debug/`.

## Шаг 3. Проверить на телефоне

```bash
./scripts/install-phone.sh
```

Скрипт найдёт телефон, поставит свежую сборку и запустит приложение. Дальше руками:

1. **VPN** — подключиться, открыть сайт, посмотреть, что идёт трафик.
2. **TgWsProxy** — запустить, нажать «Применить в Telegram», проверить загрузку сообщений.
3. **byebyeDPI** — включить, проверить открытие заблокированного сайта.

Если телефон не подключён:

```bash
adb pair <адрес:порт> <код>     # один раз, код из «Отладка по Wi-Fi»
adb connect <адрес:порт>
```

Ошибка про подписи означает, что стоит сборка из релиза: удалите приложение и поставьте заново (профили VPN сотрутся).

## Шаг 4. Выпустить релиз

```bash
./scripts/release.sh 1.0.2 "обновил ядра"
```

Скрипт поменяет версию, ещё раз проверит сборку, закоммитит, поставит тег и отправит на GitHub. Номер версии — следующий по порядку; тег ставится такой же.

Дальше GitHub сам собирает и публикует релиз (около 4 минут):
- сборка: https://github.com/kukmber/KKMProxy/actions
- релиз: https://github.com/kukmber/KKMProxy/releases/latest

Приложение у друзей проверяет обновления раз в сутки и предложит поставить новую версию.

## Что переносится вручную

**TgWsProxy.** Оригинал [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy) написан на Python, у нас порт на Kotlin. Смотрите список изменений в их релизах и переносите смысл в файлы:

```
app/src/main/java/io/github/romanvht/byedpi/telegram/proxy/
```

Ключевые: `TgWsProxyServer.kt` (сервер), `Bridge.kt` (перекачка данных), `WsPool.kt` (соединения), `MtProtoCrypto.kt` (шифрование), `ProxyConfig.kt` (настройки). После переноса обновите строку `val tgwsPortedFrom` в `app/build.gradle.kts`, чтобы приложение показывало верную версию.

**ByeByeDPI.** Исходный проект подключён как `upstream`:

```bash
git fetch upstream
git log --oneline HEAD..upstream/master    # что нового
git merge upstream/master                  # будут конфликты
```

Конфликты почти гарантированы: у нас переписан интерфейс и заменено ядро VPN. Наше — папки `activities`, `vpn`, `update` и ресурсы оформления; их — ядро ByeDPI, настройки, подбор стратегий. После слияния обновите строку `bundled` для ByeByeDPI в `app/src/main/java/io/github/romanvht/byedpi/update/Updates.kt`.

## Как переносить изменения самому

### Шаг 1. Посмотреть, что изменилось

```bash
./scripts/whats-new.sh
```

Скрипт сам берёт версию, с которой сделан наш перевод, узнаёт последнюю у авторов и печатает:

- какая версия у нас и какая вышла;
- **ссылку**, которую надо открыть в браузере, чтобы увидеть сами правки;
- список изменений, из которого уже убрано ненужное.

Ненужным считается то, что относится к чужому интерфейсу: у tg-ws-proxy это папки `ui/`, `docs/`, `packaging/` и значок в трее (у нас свой интерфейс на Android), у ByeByeDPI — переводы на другие языки и оформление репозитория. Остаётся папка `proxy/` — то самое ядро, которое мы переписали.

### Шаг 1а. Если разбираться не хочется

```bash
./scripts/make-prompt.sh
```

Скрипт соберёт готовое задание в файл `Downloads\kkm-задание-для-claude.txt`:
там и правки авторов, и наши файлы, и правила отбора. Открываете файл,
прикладываете его в новый чат с Claude (или копируете текст целиком) — и
получаете разбор: что переносить, что пропустить и какой код заменить.

Ответ лучше показать мне перед тем, как менять код: бесплатный Claude
не видит проект целиком и может предложить правку, которая не соберётся.

### Шаг 1б. Применить ответ чата

Попросите чат прислать изменённый файл целиком (в задании это уже написано),
сохраните его в «Загрузки» под тем же именем и выполните:

```bash
./scripts/apply-file.sh RawWebSocket.kt
```

Скрипт подставит файл в проект и соберёт приложение:

- **собралось** — подскажет, что проверить на телефоне и как выпустить релиз;
- **не собралось** — вернёт файл как был и положит в «Загрузки» файл
  `kkm-исправь-ошибку.txt` с текстом ошибки. Приложите его в тот же чат,
  получите исправленный вариант и повторите команду.

Так цикл замыкается без посторонней помощи: сломать проект нельзя, каждая
неудачная попытка откатывается сама.

### Шаг 2. Найти у себя то же место

| Файл оригинала (Python) | Наш файл (Kotlin) |
|---|---|
| `proxy/tg_ws_proxy.py` | `telegram/proxy/TgWsProxyServer.kt` |
| `proxy/bridge.py` | `telegram/proxy/Bridge.kt` |
| `proxy/pool.py` | `telegram/proxy/WsPool.kt` |
| `proxy/raw_websocket.py` | `telegram/proxy/RawWebSocket.kt` |
| `proxy/config.py` | `telegram/proxy/ProxyConfig.kt` |
| `proxy/crypto.py` | `telegram/proxy/MtProtoCrypto.kt` |

Полный путь: `app/src/main/java/io/github/romanvht/byedpi/`.

### Шаг 3. По каждой правке ответить на три вопроса

1. **Это про поведение прокси или про интерфейс?** Про интерфейс — пропускаем.
2. **Есть ли у нас такой механизм?** Если да — меняем по смыслу, а не построчно: Python и Kotlin пишутся по-разному.
3. **Нужно ли это на телефоне?** Настройка ради обхода ограничений на Windows может быть не нужна.

### Шаг 4. Проверить и записать версию

```bash
./gradlew :app:testDebugUnitTest assembleDebug
./scripts/install-phone.sh
```

Проверяйте именно Telegram: запустите TgWsProxy, примените в Telegram, посмотрите, грузятся ли сообщения и картинки. Потом поменяйте `val tgwsPortedFrom` в `app/build.gradle.kts` на новую версию — иначе приложение будет и дальше показывать, что мы отстаём.

### Разобранный пример: v1.10.2 → v1.10.4

В ядре там всего две содержательные правки.

**1. Проверка сертификатов (`proxy/raw_websocket.py`).** Было отключено полностью:

```python
_ssl_ctx.check_hostname = False
_ssl_ctx.verify_mode = ssl.CERT_NONE
```

Стало: сертификаты проверяются по списку доверенных центров, а имя хоста не проверяется только там, где соединение идёт с подменённым SNI (фронтинг).

Это нас касается: в `RawWebSocket.kt` стоит `TrustAllManager()` — полный аналог старого поведения. Правка по смыслу: для обычных соединений использовать системные сертификаты Android (`SSLContext.getInstance("TLS").init(null, null, null)`) и включить проверку имени хоста через `sslParameters.endpointIdentificationAlgorithm = "HTTPS"`, а для соединений с подменённым SNI оставить проверку сертификата, но без проверки имени. Смысл правки — защита от подмены соединения.

**2. Флаг `--no-secure`.** Позволяет ходить к Cloudflare по порту 80 вместо 443. Это настройка командной строки для обхода отдельных провайдеров на ПК. На телефоне у нас такого переключателя нет, и без него всё работает — пропускаем. Если когда-нибудь понадобится, это будет новое поле в `ProxyConfig.kt`.

Остальные семь правок — окно, трей, тексты и документация.

### То же самое для ByeByeDPI

Здесь проще: язык один и тот же, помогает `git`.

```bash
git fetch upstream
git log --oneline HEAD..upstream/master     # что нового
git diff HEAD...upstream/master --stat      # какие файлы затронуты
git merge upstream/master                   # слить (будут конфликты)
```

При конфликте правило простое: **интерфейс и VPN — наши, ядро обхода DPI — их.**

| Папка | Чьё |
|---|---|
| `activities/`, `vpn/`, `update/`, `res/layout`, `res/values/themes.xml` | наше, оставляем свою версию |
| `core/`, `services/ByeDpi*`, `fragments/`, `res/xml/*settings*` | их, берём их версию |
| `res/values/strings.xml` | смешанное, сливать построчно |

Незатронутый нами файл можно просто взять целиком:

```bash
git checkout --theirs app/src/main/java/io/github/romanvht/byedpi/utility/PermissionUtils.kt
git add app/src/main/java/io/github/romanvht/byedpi/utility/PermissionUtils.kt
```

Если совсем запутались — `git merge --abort` возвращает всё назад, ничего не теряется.

**Пример: v1.7.8 → v1.7.9.** Пять правок: определение состояния Private DNS (новые файлы `PrivateDnsUtils.kt`, `PrivateDnsState.kt` и правки в `ByeDpiVpnService.kt`, `MainSettingsFragment.kt`, `TestActivity.kt`), чистка мёртвого кода, ссылки в readme. Первое полезно и берётся целиком, readme и `FUNDING.yml` — их, нам не нужны. Наш `TestActivity.kt` сильно переписан, поэтому там правку придётся переносить руками: добавить показ состояния Private DNS в наш экран подбора.

## Если что-то пошло не так

| Что видите | Что делать |
|---|---|
| `Permission denied` при запуске скрипта | `chmod +x scripts/*.sh` или запустить через `bash scripts/имя.sh` |
| `Could not read from remote repository`, порт 22 | провайдер режет SSH; добавьте в `~/.ssh/config`: `Host github.com` / `HostName ssh.github.com` / `Port 443` / `User git` |
| `tag already exists` | версия уже выпускалась, возьмите следующую или удалите тег: `git tag -d v1.0.2 && git push origin :v1.0.2` |
| Сборка на GitHub упала | откройте Actions, красный запуск, шаг «Build release APKs» |
| APK не подписан | проверьте секреты `KEYSTORE_BASE64` и `KEYSTORE_PASSWORD` в настройках репозитория |
| Обновление не ставится на телефон | не выросла версия либо APK подписан другим ключом |
| WSL падает во время сборки | не хватает памяти; закройте лишние программы. Настройки WSL — в `C:\Users\rober\.wslconfig` |

## Где что лежит

| Файл | Зачем |
|---|---|
| `app/build.gradle.kts` | версия приложения (строка `appVersionName`), версия mihomo, подпись |
| `keystore.properties` | пути и пароль к ключу подписи; **в git не попадает** |
| `~/keystores/kkmproxy.jks` | сам ключ подписи; потеряете — друзьям придётся ставить приложение заново |
| `.github/workflows/release.yml` | сборка и публикация релиза по тегу |
| `.github/workflows/upstream-check.yml` | еженедельная проверка оригиналов |
| `app/src/main/java/.../update/Updates.kt` | список компонентов и репозиторий обновлений |
